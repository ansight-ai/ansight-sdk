# Motion capture

Motion capture is available in the separate `Ansight.Motion`, `ansight-motion-android`, and `AnsightMotion` packages, and through the React Native, Capacitor, and Flutter SDK APIs. The packages depend on the core runtime. Enable capture explicitly with the SDK options builder's `WithMotionCapture` or `withMotionCapture` option. By default, both shake and accelerometer forwarding are enabled within that option; each can be disabled individually. Accelerometer samples are limited to one every 20 ms by default, with a configurable interval from 10 to 1,000 ms.

The app forwards motion it already observes. Ansight does not create a `CMMotionManager`, register an Android `SensorEventListener`, or request sensor permissions. A host can inject motion into an iOS Simulator or Android emulator; that injected input is recorded as `motion.injected.*` evidence when a session is available. For captured app-side evidence, forward the app's shake handler or existing accelerometer samples to the SDK. A UIKit `motionEnded(_:with:)` handler can call `AnsightMotion.recordShake()`. An app's Core Motion callback can call `AnsightMotion.recordAccelerometer(x:y:z:)` after converting acceleration from g to m/s² (multiply by 9.80665). Android can forward an existing `SensorEvent`'s accelerometer values directly to `AnsightMotion.recordAccelerometer` because those values are already in m/s².

The other SDKs expose `recordShake` and `recordAccelerometer` on their runtime interfaces. Calls made while the runtime is inactive or motion capture is disabled are ignored. The SDK records `Motion` events with labels `motion.shake` and `motion.accelerometer`; sample details contain `x`, `y`, `z`, `unit: "m/s2"`, and `source: "app"`. The local host writes them to the session's `motion/events.json` capture folder and includes them in the `motion` timeline category.

UIKit shake events use the responder chain, independently of Core Motion. Forwarding a shake event does not start or interfere with the app's `CMMotionManager`. The app remains responsible for setting up any raw sensor sampling it wants to use, including its own platform permission and privacy decisions.
